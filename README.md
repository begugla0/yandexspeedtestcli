# yaspeed

Замер скорости интернета прямо в терминале — через публичный API [Яндекс.Интернетометра](https://yandex.ru/internet).

Один файл, никаких зависимостей, только стандартная библиотека Python 3.8+.

  адрес   1.1.1.1   регион  Москва

  •  cloudcdn-m9-2.cdn.yandex.net          2.1 ms   med 2.4   jitter 0.6

  •  cloudcdn-std-12.cdn.yandex.net        3.5 ms   med 3.8   jitter 0.6

## Запуск одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/begugla0/yandexspeedtestcli/main/yaspeed.py | python3 -
```

Ничего не устанавливается и не остаётся на диске — скрипт выполняется и исчезает.

Флаги при таком запуске передаются после `-`:

```bash
curl -fsSL https://raw.githubusercontent.com/begugla0/yandexspeedtestcli/main/yaspeed.py | python3 - --json
```

## Установка

Чтобы команда `yaspeed` осталась в системе:

```bash
sudo curl -fsSL https://raw.githubusercontent.com/begugla0/yandexspeedtestcli/main/yaspeed.py \
     -o /usr/local/bin/yaspeed && sudo chmod +x /usr/local/bin/yaspeed
```

Дальше просто:

```bash
yaspeed
```

Без прав root положи файл в `~/.local/bin` — он обычно уже в `PATH`.

Или через git:

```bash
git clone https://github.com/begugla0/yandexspeedtestcli
cd yandexspeedtestcli && python3 yaspeed.py
```

## Использование

```bash
yaspeed                          # полный замер
yaspeed -d 15                    # по 15 секунд на фазу
yaspeed --no-upload              # только загрузка
yaspeed --json                   # машиночитаемый вывод
yaspeed -q                       # только итоговая таблица
yaspeed --dl-nodes best --dl-streams 8   # выжать максимум с ближайшего узла
```

| Флаг | Что делает |
|---|---|
| `-d`, `--duration` | длительность каждой фазы, по умолчанию 6 с |
| `--dl-nodes all\|best` | качать со всех узлов сразу (как веб-клиент) или только с ближайшего |
| `--dl-streams N` | потоков загрузки на каждый узел |
| `--ul-streams N` | потоков отдачи |
| `--ul-mode chunked\|fixed` | один длинный POST или много коротких |
| `--pings N` | сколько пингов на узел |
| `--node LID` | замер на конкретном узле вместо автовыбора |
| `--no-download`, `--no-upload` | пропустить фазу |
| `--no-bufferbloat` | не мерить задержку под нагрузкой |
| `--probes-only` | показать сырой ответ `get-probes` |
| `-j`, `--json` | вывод в JSON |
| `-q`, `--quiet` | только итог |
| `--no-color`, `--ascii` | для логов и небогатых терминалов |

Вывод сам подстраивается: без TTY анимация отключается, `NO_COLOR` уважается, при не-UTF-8 локали графика переключается на ASCII.

## Что именно измеряется

**Задержка.** Все три CDN-узла Яндекса опрашиваются параллельно по одному переиспользуемому TLS-соединению. Соединение поднимается прогревочным запросом до начала замера, поэтому в RTT попадает только round-trip, без хендшейка. Считаются минимум, медиана, p95 и джиттер; для итога берётся минимум по ближайшему узлу.

**Загрузка.** По умолчанию повторяет поведение веб-клиента: один поток на каждый из трёх узлов одновременно, файл 50 МБ, а как только он докачан — сразу следующий запрос. Первая четверть окна отбрасывается как разгон TCP. В выводе видно вклад каждого узла отдельно.

**Отдача.** Данные льются длинным POST с `Transfer-Encoding: chunked`, а параллельно читается SSE-поток серверной статистики — сервер сам сообщает, сколько байт до него реально дошло за каждые ~50 мс. Итоговая цифра берётся именно оттуда: клиентский счётчик видит только то, что ушло в сокет, и на асимметричных каналах завышает. Если сервер статистику не отдал, скрипт честно помечает результат как `(счёт клиента)`.

**Bufferbloat.** Во время обеих фаз параллельно идёт пинг, и считается, насколько выросла медианная задержка относительно ненагруженного минимума. Оценка: `A+` до 5 мс, `A` до 30, `B` до 60, `C` до 200, `D` до 400, дальше `F`. Высокий bufferbloat — причина того, что звонки рассыпаются, когда кто-то в квартире качает торрент, даже если «скорость гигабит».

## JSON

`--json` отдаёт полный набор для скриптов и мониторинга:

```bash
yaspeed --json | jq '{down: .download.avg_bps, up: .upload.avg_bps, ping: .best_latency.min}'
```

Там же лежат `mid` замера, `per_node` с побайтовым вкладом каждого узла, сырые тайминги задержки и `bufferbloat` в миллисекундах.

## Оговорки

Скорость упирается не только в канал. Если тестируешь на слабом VPS или через Wi-Fi, потолком может оказаться процессор (TLS-шифрование на гигабите не бесплатно) или радиоканал, а не провайдер. Замер идёт до московских узлов Яндекса — для абонента из другой страны цифра говорит о качестве маршрута до России, а не о скорости «вообще».

Результат не совпадёт с сайтом Яндекса до последнего мегабита: веб-клиент считает по `PerformanceResourceTiming` и включает в зачёт разгон соединения, здесь же первая четверть окна отбрасывается. На стабильном канале разница в пределах пары процентов, на дёрганом эта цифра будет выше.

## Дисклеймер

Неофициальный проект, никак не связанный с Яндексом и не поддерживаемый им. Использует публичные эндпоинты, доступные из браузера на `yandex.ru/internet`. Если Яндекс изменит API, скрипт может перестать работать — заводите issue.
